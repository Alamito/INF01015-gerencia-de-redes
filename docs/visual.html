2

Quando o agente é chamado?

O monitor guarda o estado anterior de cada alvo. A IA só é acionada na transição OK → FAIL. Falhas seguintes do mesmo incidente são ignoradas, para não repetir investigações e ações.

Depois que o agente termina, o monitor reverifica o alvo por conta própria e anexa o resultado ao relatório (“Verificação do monitor”). É uma confirmação independente do que o agente diz ter feito.
3

As ferramentas e o que cada resultado significa

Cada ferramenta testa uma camada. O agente raciocina de baixo para cima e para quando acha a camada que falhou. Os docstrings das funções são o que o LLM lê para escolher qual usar.

Nomes · DNS
dns_lookup

Se o nome não resolve, o problema é DNS e não adianta testar o resto. O agente faz um teste de controle com um domínio conhecido: assim separa “resolvedor quebrado” de “nome inexistente”.

socket.getaddrinfo(name)
Rede · ICMP
ping · traceroute

Ping com 4 pacotes: o parser conta linhas com “TTL”, que existem em qualquer idioma do SO. O traceroute é lento e só entra quando o ping de um host remoto falha.

perda % · latência média · até 10 saltos
Transporte · TCP
check_port

Abre uma conexão TCP (timeout de 3 s). O estado diz onde está o problema:

openserviço escutando
closedrecusada: host vivo, serviço parado
timeoutfiltrado ou host fora do ar
Aplicação · HTTP
check_http

DNS e porta funcionam, mas o HTTP está lento ou com erro? Então o problema é da aplicação, e reiniciar não é a resposta certa.

requests.get → status + tempo (ms)
Remediação
restart_service

A única ferramenta que altera algo. Só aceita web e db, por uma lista fixa no código. Qualquer outro nome é rejeitado.

comando JSON → controlador do lab :8099
4

Quando o agente pode reiniciar um serviço?

A política está no prompt (agent_prompt.md) e é reforçada no código: mesmo que o modelo erre, restart_service só aceita os serviços do laboratório.

5

Por que o agente não consegue fazer estrago

Princípio do menor privilégio: o Claude Code recebe a menor superfície possível. As flags estão em agent.py.

1
Sem ferramentas nativas--tools ""

O agente não tem shell nem acesso a arquivos.

2
Só o nosso servidor MCP--strict-mcp-config
--allowedTools mcp__netsentinel

Ele só enxerga as 6 funções de net_tools.py.

3
Sem perguntas--permission-mode dontAsk

Roda sem supervisão: o que não está permitido é negado.

4
Validação no código

Lista fixa para restart_service; hosts passam por regex, e um argumento como -n 1 x é rejeitado.

5
Sem custo de API

ANTHROPIC_API_KEY é removida do ambiente do processo, então o uso sai da assinatura.

6

Por que o laboratório tem um controlador separado

Problema real encontrado nos testes: o Claude Code encerra toda a árvore de processos ao terminar.

Antes SERVIÇO MORRIA
claude -p
 └─ mcp_server.py
     └─ serviço web  ← reiniciado pelo agente

agente termina → árvore encerrada
serviço morre
O monitor reverificava e o alvo ainda falhava.
Depois SERVIÇO SOBREVIVE
terminal do usuário
 └─ lab.py run  (controlador :8099)
     ├─ web :8080
     └─ db  :6543

claude → mcp → net_tools ──JSON──► :8099
O agente só envia um comando; o serviço vive em outro processo.
